01 Read the signal

Four labels.
Four different promises.

The narrowest accurate label wins. A supported protocol family never silently becomes a claim about every model in that family.

Supported
An operator-approved working path on the exact named model; stated limitations can still apply.
Verified bounded
The named behavior was observed on the exact named hardware, with remaining gates stated.
Experimental
Code exists, but model coverage or real-hardware validation is incomplete.
Research / later
No generally usable saved-device path is claimed yet.

03 Before you build

Compatibility is a test result,
not a vibe.

Firmware can implement a protocol while a specific model, firmware revision, reconnect path, or mixed-device sequence remains untested. Ble(e)p keeps those boundaries visible so you can decide what belongs in your studio.
